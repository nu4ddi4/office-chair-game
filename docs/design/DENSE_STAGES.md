# 퇴근.exe — 밀도 높은 3개 스테이지 상세안

작성: 2026-11-02 · 상태: 구현 전 스크립트 초안 v1 · 대상: 기존 6개 업무를 대체할 짧은 체험판.

이 문서 묶음은 3개 스테이지의 기획 원안이다. 현재는 1스테이지 출력실을 구현해 기존 여섯 단계를 교체했으며, 2·3스테이지는 설계 단계다. 실제 실행 구성과 구현 계약은 [출력실 구현 문서](../TERMINAL_STAGES.md)에서 확인한다. 아래 대사·공간·판정·연출과 초 단위 수치는 원안이며 구현·플레이 검증에서 조정한다.

## 1. 체험판 전체의 약속

플레이어는 첫 출근한 사원이다. 퇴근 신청서 한 장을 뽑고, 팀장에게 결재받고, 마지막 PC를 끈다. 회사는 모든 사태를 정상 업무처럼 취급한다.

세 개의 목표는 처음부터 일상적인 문장으로 제시한다. 각 목표를 수행하는 실제 행동이 점점 커진다. 웃음을 만들기 위해 주인공에게 재치 있는 독백을 시키지 않는다. 플레이어가 직접 누르고, 쫓아가고, 멈추고, 길을 만들어 보게 한다.

| 항목 | 설계 목표 |
| --- | --- |
| 첫 플레이 | 실패·탐색 포함 전체 14~20분. 25분을 넘기면 이동·반복부터 줄임 |
| 숙련 플레이 | 전체 6~9분. 대사·연출을 반복해서 기다리게 하지 않음 |
| 첫 입력 | 새 게임 선택 후 15초 이내 이동, 30초 이내 첫 장치 조작 |
| 적응 | 1스테이지 앞 35~50초 안에 이동·F·터미널 Enter·help 체험 |
| 초반 실패 | 1·2스테이지에서는 넘어짐·종이·의자로 복구 가능한 사고를 학습 |
| 첫 PC 폭발 | 3스테이지의 잘못된 장치 조작에서 처음 가능. 사전 도움말·소개에서 공개하지 않음 |
| 조작 밀도 | 주 경로에서 수동 이동·조작 없이 15초 이상 기다리는 구간을 만들지 않음 |
| 대사 | 한 발화 보통 1문장, 최대 2줄. 한 장면에 한 화자만 말함 |
| 재시도 | 실패 원인을 볼 수 있는 0.6~1.5초 후 재시도 가능. 선택 후 1초 이내 재개 목표 |
| 진행 손실 | 보통 10~25초. 긴 손실은 3스테이지의 선택 지름길에서만 최대 40초 |
| 저장 | 소구간 통과·획득 서류·완료 스테이지는 보존. 저장 성공 후 다음 구간 진입 |
| 시점 | 플레이 중 1인칭 고정. 조작을 빼앗는 자동 카메라 회전 없음 |

## 2. 세 스테이지를 묶는 코미디

| 반복되는 요소 | 첫 등장 | 변형 | 회수 |
| --- | --- | --- | --- |
| ‘한 장’ | 서류 한 장을 부탁받음 | 수백 장이 공간을 바꿈 | 최종 정전 뒤 프린터가 마지막 한 장을 배출 |
| ‘잠깐’ | 팀장의 짧은 확인 | 회의 의자가 길을 따라옴 | 전원이 꺼진 뒤 팀장도 말끝을 이어가지 못함 |
| 사무용 의자 | 출력실에서 종이에 밀리는 배경 소품 | 결재석이 이동하는 장치 | 마지막 PC가 의자 바퀴로 도주 |
| 정상 처리음 | 첫 출력 성공음 | 엉망인 결재 장면에도 같은 성공음 | 대형 정전 뒤 아주 작은 퇴근 단말에서 한 번 더 재생 |
| 회사의 진지함 | 서류를 구김 없이 달라고 함 | 사무실이 움직여도 결재 위치만 따짐 | 정전 후 종이 원본을 찾는 작은 행동으로 끝냄 |

반복 요소는 매번 기능이 달라진다. 같은 폭발·같은 욕설·같은 실패 문구를 세 번 재생하는 방식으로 늘리지 않는다.

## 3. 공통 조작과 상호작용

### PC

- WASD 이동, 마우스 시점, Space 점프, Shift 달리기, C 앉기, F 상호작용.
- 종이·쐐기 등 손에 드는 물건은 한 개 슬롯. F로 집고, 해당 받침대를 바라보고 F로 놓는다.
- 놓을 곳이 없을 때 F는 물건을 발 앞에 둔다. 중요 서류는 2초 뒤 마지막 받침대로 돌아온다.
- 물건을 들었다고 시야 중앙을 가리지 않는다. 화면 아래 바깥쪽에 일부만 보인다.
- 유효한 상호작용 대상이 있으면 그 행동이 바닥에 내려놓기보다 우선한다. 서류를 든 채 NPC와 대화해도 자동으로 버리지 않는다.
- 일반 현장 상호작용은 기존 3.4m 탐색을 사용한다. 정밀 투입구·브레이크·최종 전원선의 실행 거리는 각 장치에 별도 정의한다.
- 상호작용 표시는 행동명 한 줄로 제한한다. ‘F — 집기’, ‘F — 브레이크’, ‘F — 서류 놓기’처럼 쓴다.
- 대화 선택은 한 번에 최대 3개. NPC 앞에서만 열린다. 스크롤 없는 2줄 이하 선택문을 사용한다.

### 터미널

- 입력창은 Enter 실행 후 계속 포커스를 유지한다. ↑↓ 이력, Tab 완성, clear, history, exit를 유지한다.
- help는 문법·조회 수단·범위를 보여 준다. 현재 문제의 정답 인수와 숨은 사고 결과는 쓰지 않는다.
- 옆에는 현재 목표 하나만 둔다. 명령어 책과 실행용 하단 버튼을 추가하지 않는다.
- 결과는 처리 ID, 상태, 수치와 같은 업무 시스템 출력으로만 쓴다.
- 정상 조회·잘못된 문법·존재하지 않는 파일 조회는 일반 오류로 끝낸다. 3스테이지의 실제 장치 조작 실패를 별도 연출 대상으로 삼는다.
- 먼저 현장을 보고 장치를 직접 만져도 통과할 수 있다. `help → ls → cat` 순서를 강제하는 숨은 플래그를 두지 않는다.
- 명령어·장치 ID·작업 ID는 대소문자와 양끝 공백을 정규화한다. 과거에 본 표기와 입력 표기의 차이로 오조치 판정을 만들지 않는다.
- 게임 안 명령은 정해진 상태 전이에만 연결한다. 운영체제 셸·실제 네트워크를 실행하지 않는다.

### Android

- 동일한 행동을 이동 스틱·시점 영역·상호작용·점프로 수행한다. 미세한 마우스 흔들기나 우클릭 전용 규칙을 넣지 않는다.
- 위험 구간에서 키보드 입력과 점프를 동시에 요구하지 않는다. 장치로 환경을 설정한 뒤 현장으로 복귀한다.
- 누르고 있기 대신 F 한 번/상호작용 한 번으로 상태를 바꾸는 조작을 기본으로 한다.
- 대화·터미널·일시정지에서는 이동 장치와 위험 타이머를 함께 멈춘다. 읽는 속도를 실패 조건으로 삼지 않는다.
- 이 정지는 이미 확정한 장치 조작의 결과 연출과 구분한다. 3스테이지에서 냉각 서비스를 직접 종료한 뒤 재생되는 파손은 그 입력의 결과이며, 단순 열람 중 진행하는 위험 타이머가 아니다. 결과 연출도 일시정지 메뉴에서는 멈춘다.
- 현장에서 자동으로 나오는 짧은 NPC 대사는 비모달 자막이다. F로 여는 선택 대화만 시간 정지를 적용한다. 자동 자막 때문에 물체가 매번 멈추거나 입력을 빼앗지 않는다.

## 4. 공간과 품질 기준

기존 상세 사무실의 모델, 문, 보호 충돌체는 유지한다. 출력실·결재석은 현재 사무실의 장비와 NPC 부근에 가변 소품을 덧붙인다. 마지막 구간은 기존 임시 옥상 코스가 담당하던 별도 공간에 사무용 설비로 만든 입체 코스를 배치한다.

각 문서의 치수는 새 가변 소품 사이의 상대 거리다. 기존 사무실의 실제 좌표라고 간주하지 않는다. 월드 좌표는 authoring anchor에서 읽고, 보호 맵을 고쳐 치수를 맞추지 않는다.

### 더미 단계에서도 지킬 것

1. 오르는 물체가 프린터 받침·종이 더미·이동식 작업대·설비 점검 발판처럼 보인다.
2. 이동 경로에 바퀴, 레일, 전선 또는 받침 구조가 있어 움직임의 이유를 볼 수 있다.
3. 첫 시야 안에서 목표, 조작할 물체, 실패 후 떨어질 곳을 구분할 수 있다.
4. 낙하 중 되돌아갈 장소가 보인다. 순간 암전만으로 모든 실패를 처리하지 않는다.
5. 이벤트가 시야 밖에서 시작하면 소리와 이동 경로로 발견할 기회를 준다. 카메라를 강제로 돌리지 않는다.
6. 주요 사고 한 번에 물체 1개 또는 한 무리만 먼저 움직인다. 원인과 결과를 읽은 뒤 다음 반응이 붙는다.
7. 필수 점프에서 발판 폭 0.9m 미만, 맹목 점프, 공중 180도 회전을 요구하지 않는다.
8. 조작·충돌·대사는 정상 작동해야 한다. 어설픈 입력과 끊기는 프레임을 농담으로 취급하지 않는다.

## 5. 움직임과 물리의 계약

현재 `LabPlayer`는 걷기 2.6m/s, 달리기 4.2m/s, 점프 초기 속도 4.3m/s, 중력 12.5m/s²를 쓴다. 이상적인 평지 점프의 최대 상승은 약 0.74m, 공중 시간은 약 0.69초다. 아래 치수는 충돌·모서리·입력 여유를 남긴다.

| 조건 | 처음 적용할 값 |
| --- | --- |
| 필수 연속 상승 | 한 번에 0.30~0.45m |
| 필수 수평 간격 | 발판 가장자리 사이 0.65~1.10m |
| 필수 착지 폭 | 1.2m 이상, 움직이는 착지는 1.5m 이상 |
| 이동 발판 | 0.7~1.1m/s, 끝에서 1.0초 정지 |
| 가장자리 입력 보정 | 점프 버퍼 0.12초, 코요테 타임 0.10초를 구현 때 추가 |
| 1차 밀림 | 0.5~0.8m, 충분한 회복 공간 제공 |
| 최대 연쇄 밀림 | 3번 또는 1.8초 중 먼저 도달하는 쪽에서 끝냄 |
| 떨어짐 | 추락 바닥 도착 시 마지막 소구간으로 복귀. 카메라 구르기 없음 |

서류 무더기는 미리 정한 충돌 블록 6~10개와 표면 종이 연출로 만든다. 수백 장의 개별 RigidBody가 결과를 결정하게 하지 않는다. 의자·PC의 주요 이동도 경로와 상태가 결정하며, 장식용 바퀴·몸통의 흔들림만 물리처럼 보이게 한다.

플레이어가 알고 연습한 규칙은 재시도 때 유지한다. 모양만 같은 발판이 시도마다 무작위로 사라지지 않는다. 장식 파편의 난수는 통과 판정에 영향을 주지 않는다.

## 6. 실패·재도전·저장

| 실패 종류 | 화면 처리 | 보존 | 초기화 |
| --- | --- | --- | --- |
| 가벼운 넘어짐·종이 바람 | 현장에서 회복, 조작은 짧게만 감속 | 모든 진행 | 현재 밀림 속도 |
| 서류 흘림 | 서류가 눈앞에 떨어지고 가까운 받침대로 복귀 | 완료 소구간 | 들고 있던 상태 |
| 구간 추락 | 추락 지점까지 최대 1.5초 표시 후 재도전 | 앞선 스테이지, 구간 체크포인트 | 현 구간 가변 소품 |
| PC 폭발 | 실제 모델 파손·짧은 정적·재도전 | 앞선 스테이지, 마지막 체크포인트, 발견한 일반 기록 | 폭발 구간 장치·파편 |
| 일반 종료·저장 실패 | 기존 보존 동작을 따름 | 마지막 정상 저장과 원본 | 자동 초기화하지 않음 |

사고 연출이 재생되는 동안 재도전 입력을 예약할 수 있다. 원인에 해당하는 첫 충돌을 0.6초는 보여 주고, 그 뒤에는 즉시 복구할 수 있게 한다. 반복 시도에서는 첫 등장 대사를 줄인다. 메뉴를 열어 기다리면 위험을 회피할 수 있는 정도의 설계는 허용하되, 메뉴를 닫을 때 위험이 한꺼번에 누적되어 적용되지 않게 한다.

새 설계의 소구간 상태는 기존 엄격한 `stage` 검증에 임의 필드를 끼워 넣어 저장하지 않는다. 구현 시 진행 버전을 올리고 `dense3_v1` 캠페인과 기존 6단계 진행을 구분한다. 기존 6단계 완료를 새 3단계 완료로 환산하지 않는다.

기존 저장을 발견하면 이전 진행의 계속하기를 유지한다. 사용자가 새 체험판 시작을 선택하면 기존 저장을 먼저 보존하고, 보존 성공 뒤 1스테이지부터 시작한다. 새 진행의 체크포인트와 장치 상태는 허용된 ID·범위만 읽으며, 재실행 시 가장 가까운 안전면으로 정규화한다. 기존 플레이어의 파일을 덮어쓰는 자동 새 게임은 금지한다. 이 계약은 구현 시 기존 8/9필드 저장 회귀 검사와 함께 검증한다.

## 7. 웃음 장면의 공통 편집 규칙

- 장면마다 ‘평범한 기대 → 작은 이상 → 플레이어의 개입 → 과한 결과 → 한 번 더 따라오는 결과’를 적는다.
- 한 번의 입력과 첫 결과는 0.25초 이내에 연결한다. 큰 결과가 늦게 오더라도 작동등·모터음으로 원인을 잇는다.
- 결과를 알아챈 뒤 0.4~1.2초간 플레이어가 피하거나 멈출 수 있는 구간을 둔다. 행동이 성공하면 성공한 대응 자체를 인정한다.
- 큰 소리 직후 NPC가 바로 농담하지 않는다. 0.4~0.8초 비워 플레이어가 먼저 반응할 시간을 둔다.
- 기본 농담은 물체와 행동으로 성립해야 한다. 대사와 인터넷 밈을 제거해도 장면이 읽혀야 한다.
- 성공 경로에도 주요 코미디 장면을 넣는다. 실패를 전혀 하지 않은 사람에게도 세 번 이상의 큰 사건이 발생한다.
- NPC는 플레이어의 지능·실력·인격을 조롱하지 않는다. 주변의 말도 안 되는 상황을 사무 규정으로 처리한다.
- 진짜 설정·저장·종료·업데이트 동의 UI의 위치와 입력은 항상 안정적으로 유지한다. 장난치는 화면은 작중 장치 내부에 한정한다.

## 8. 제작 순서와 판정

| 차수 | 만드는 것 | 통과 조건 |
| --- | --- | --- |
| A | 1스테이지의 출력 시작 → 종이 밀림 → 정지 → 서류 회수 | 처음 보는 사람이 첫 조작을 찾고, 원인과 결과를 설명할 수 있음 |
| B | 2스테이지의 대화 → 결재석 이동 → 브레이크/우회 → 도장 | 대화 선택을 암기하지 않고 현장 규칙으로 문제를 해결함 |
| C | 3스테이지의 도망 PC → 두 경로 → 전원 차단 | 익숙한 소품을 능숙하게 쓰는 느낌과 마지막 반전이 살아 있음 |
| D | 이동·음향·모델 마감, 변형 대사, 선택 지름길 | 성공 경로도 재미있고 반복 실패 때 연출이 진행을 붙잡지 않음 |

처음부터 3개 전체를 그래픽까지 완성하지 않는다. 각 스테이지의 핵심 사건 60~90초를 먼저 조작 가능하게 만들고 [반응 검증표](COMEDY_REFERENCE_ANALYSIS.md#7-실제로-웃는지-확인하는-플레이테스트)로 확인한다. 핵심 사건이 안 먹히면 소품 개수를 늘리기 전에 원인·타이밍·회복 여지를 고친다.

## 9. 대사와 HUD의 표기

각 상세안의 ‘화면’, ‘터미널’, ‘대사’ 블록만 플레이어에게 노출할 원문이다. 나머지 문장은 제작 지시다. 대사 ID는 영문 고정 ID로 두고 한국어 문구와 분리한다.

목표 HUD는 한 번에 한 줄만 표시한다. 스테이지 선택 화면은 입장 전 `???`, 입장 후 제목을 표시한다. 파일을 읽은 것만으로 정답을 선택하거나 장치가 자동 조작되지 않는다. 정답 대상 테두리·추천 명령 버튼·다음 행동을 설명하는 해설문은 추가하지 않는다.
