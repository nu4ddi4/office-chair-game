# 01 — 한 장만 뽑아 주세요

[전체 설계](DENSE_STAGES.md) · [웃음 분석](COMEDY_REFERENCE_ANALYSIS.md) · [다음 스테이지](STAGE_02_APPROVAL.md).

상태: 첫 구현의 기획 원안. 실제 실행 동작·조정된 배치·저장 계약은 [출력실 구현 문서](../TERMINAL_STAGES.md)를 따른다. 아래 대사·터미널 블록은 원안의 노출 문구이며 나머지는 제작 지시다.

## 1. 이 스테이지가 하는 일

퇴근 신청서 한 장을 출력하는 평범한 업무로 시작한다. 출력 성공 직후 종이가 계속 나오면서 가구를 밀고 길을 만든다. 플레이어는 출력을 멈출 방법과 생긴 지형을 이용할 방법을 함께 판단한다.

첫 35~50초는 터미널과 이동에 적응하는 시간이다. 이후에는 이미 한 행동의 결과를 수습하게 한다. 서류 찾기 퀴즈와 점프 연습을 따로 떼어 두지 않는다.

| 항목 | 목표 |
| --- | --- |
| 화면 제목 | 한 장만 뽑아 주세요 |
| 최초 목표 | 퇴근 신청서를 한 장 출력하세요. |
| 사건 후 목표 | 신청서를 회수하고 출력을 멈추세요. |
| 첫 플레이 | 4~6분 |
| 숙련 경로 | 1분 40초~2분 20초 |
| 핵심 판단 | 언제 출력을 멈출지, 만들어진 종이를 길로 쓸지, 옆길을 이용할지 |
| 주요 조작 | 터미널 입력, F 일시정지/브레이크/회수, 이동·점프 |
| 대표 장면 | P01: 출력물이 빈 의자를 밀고 문틀에 끼움 |
| 주요 소구간 | P-A 적응, P-B 폭주 수습, P-C 서류 회수 |
| PC 파손 | 없음. 오입력·실험을 허용 |

## 2. 공간과 첫 시야

현재 상세 사무실의 출력 장비 부근에 새 가변 소품을 둔다. 처음부터 장비와 목적지가 한 화면에 들어오게 하며 NPC를 찾으러 돌아다니는 구간은 넣지 않는다.

```text
                    북쪽: 결재석으로 이어지는 통로
                 [출구 받침대 / 체크포인트 P-C]
                            |
 [접힌 발판차] ── [회수구] [프린터 PR-01] ── [일시정지 페달]
       |          ↑          ║
       |       종이 경사     ║ 종이 배출 방향
       └──── [종이 받침 3개] ║
                            ↓
                  [바퀴 의자] → [문틀 / 멈춤턱]
                            |
                  [PC / 키보드 / 낮은 작업대]
                            |
                시작 위치 / 서유진 / 열린 복귀 공간
```

배치 도식은 새 소품의 관계를 나타낸다. 실제 기존 벽·문을 도식에 맞춰 이동하지 않는다.

### 치수와 접근

- PC에서 프린터까지 걸어서 2~3초. 화면을 닫으면 배출구와 의자가 같은 시야 안에 있다.
- 종이가 의자를 미는 길은 폭 1.8m, 길이 약 4.5m. 양옆에는 폭 1.2m 이상의 피할 공간이 있다.
- 의자 종점은 기존 문 Pivot 앞이 아닌 별도 가변 문틀 소품이다. 실제 출입문이 막혀 갇히지 않게 한다.
- 종이 받침 높이는 0.35m, 0.70m, 1.05m. 각 받침 폭 1.4m 이상, 사이 간격 최대 0.75m.
- 회수구는 높은 프린터의 상부 트레이. 아래에서는 앞 덮개가 종이를 가려 직접 집기 어렵고, 종이 구조물 또는 옆 발판차에서 접근한다.
- 회수 상호작용 거리는 0.95m. 레이캐스트가 덮개에 가려지면 회수할 수 없다. 실제 점프로 손이 닿는 우회는 인정한다.
- 모든 추락은 출력실 바닥으로 돌아온다. 종이 더미 옆에 즉사 구멍을 만들지 않는다.

## 3. 등장인물과 톤

**서유진 (`seo`, 협력업체 정비).** 프린터 옆에서 상태를 보고 있다. 사건을 크게 놀라지 않고 처리한다. 목표와 장치 상태를 말하되 명령의 정답을 입으로 읽어 주지 않는다.

**오세진 (`oh`, 보안팀장).** 다음 공간에 있다. 이번에는 멀리서 고개를 드는 정도만 한다. 프린터 소리마다 같은 대사를 반복하지 않는다.

주인공 대사는 없다. 플레이어가 실제로 외칠 틈을 남긴다.

## 4. 시작 — P-A 적응

### P-00 / 새 게임에서 현장으로

소리: 형광등의 낮은 소음, 멀리서 한 번 들리는 키보드. 경고 음악 없음.

시작 위치에서 2m 앞에 켜진 PC, 4m 앞에 프린터가 보인다. PC 옆 화면에는 퇴근 신청서의 작은 미리보기가 있다. 프린터 옆 의자는 아무도 앉지 않은 상태다.

화면:

```text
STAGE 01 · 한 장만 뽑아 주세요
퇴근 신청서를 한 장 출력하세요.
```

서유진 `P_SEO_OPEN`:

> 퇴근 신청서 한 장만 뽑아 주세요.

1.0초 뒤, 아직 PC를 열지 않았다면 한 번만:

> 프린터는 저쪽이에요. 전 여기 있을게요.

NPC에게 다시 F를 누르면:

> 서류 나오면 부르세요.

대화가 장치를 열기 위한 필수 플래그가 되지 않는다. 먼저 PC로 간 사람도 동일하게 진행한다.

### P-01 / 첫 터미널

PC F 표시는 `F — 터미널`.

터미널 최초 표시:

```text
PR-01
READY
operator@print:~$
```

`help`:

```text
help             command list
ls               list files
cat <file>       read file
status           printer status
queue            print queue
print <file>     submit print job
pause <job>      pause job
resume <job>     resume job
cancel <job>     cancel job
clear  history  exit
```

`ls`:

```text
clockout.form
notice.txt
service.log
```

`cat clockout.form`:

```text
퇴근 신청서
신청인: 신입사원
결재: 미접수
출력 매수: 1
```

`cat notice.txt`:

```text
PR-01
배출구 앞 적재 금지
상부 트레이 점검일: 오늘
```

`cat service.log`:

```text
17:58:11 tray_sensor=NO_ACK
17:58:12 retry_delivery=ON
17:58:13 operator_session=OPEN
```

`status` (출력 전):

```text
PR-01 READY
PAPER 96%
JOBS 0
```

`print clockout.form`:

```text
JOB R41 ACCEPTED
FILE clockout.form
COPIES 1
```

명령과 파일명은 도움말의 문법을 따르며 앞뒤 공백·대소문자 차이는 허용한다. `print clockout.form 1`처럼 실제 도움말에 없는 문법은 일반 문법 오류로 끝낸다. 첫 입력은 임의 명령을 알아야만 통과하도록 만들지 않는다. Tab 완성은 파일명만 완성하며 자동 실행하지 않는다.

출력 수락 시 상부 트레이에 도착할 신청서 한 장을 논리적으로 예약한다. 즉시 pause나 cancel을 입력해도 이 한 장은 배출을 완료한다. 남은 반복 출력만 멈춘다. 따라서 첫 배출 전에 취소한 사람도 발판차나 직접 접근으로 서류를 회수할 수 있다.

### P-02 / 입력 오류와 멈춤

- 알 수 없는 명령: `<name>: command not found`.
- 없는 파일: `cat: <file>: no such file`.
- 출력할 수 없는 텍스트 파일: `print: unsupported document type`.
- 유효하지 않은 작업 ID: `job: not found`.
- 빈 Enter: 프롬프트만 유지, 오류·실패 횟수 증가 없음.
- 이 구간에서 20초간 진행이 없으면 PC 화면의 커서만 천천히 점멸한다. 정답 명령을 띄우지 않는다.
- 40초간 장치를 못 찾았으면 기존 상호작용 표지의 크기만 한 번 살짝 변한다. 사용자가 일시정지 중인 시간은 제외한다.

## 5. 첫 사건 — P-B 출력 폭주

### P-03 / 성공한 줄 아는 시간

출력 명령 뒤 일어나는 사건은 한 번만 시작한다. 중복 Enter가 새 스크립트를 겹쳐 실행하지 않는다. 접수 성공음과 최초 한 장의 배출 표시는 명령 직후 보인다. 아래 시각 0.00은 터미널을 닫고 현장으로 돌아온 순간이며, 위험한 의자 이동은 그때부터 진행한다.

| 상대 시각 | 소품·소리 | 플레이어 제어 |
| --- | --- | --- |
| 0.00 | 롤러가 재개되고 RUN 표시등 켜짐 | 자유 이동·시점 |
| 0.25 | 배출구에 있던 서류 뒤에서 다음 종이가 밀려옴 | 페달·브레이크 접근 가능 |
| 0.65 | 같은 서류가 뒤에서 계속 밀려 나옴 | exit/Esc로 즉시 현장 복귀 가능 |
| 1.10 | 종이 띠가 바닥까지 내려가 빈 의자 바퀴에 닿음 | 현장에서는 자유 이동 |
| 1.65 | 의자가 0.2m 움직이고 바퀴가 한 번 끼익거림 | 피하거나 브레이크 조작 가능 |
| 2.40 | 의자가 길을 따라 1.5m 밀림 | 점프·옆으로 피하기 가능 |
| 3.20 | 문틀에 의자가 옆으로 끼고 종이가 그 뒤로 쌓임 | 조작 강제 정지 없음 |
| 3.80 | 빈 의자 하나가 마지막으로 작게 툭 부딪힘 | 첫 의자와 겹치지 않는 낮은 속도 |

**P01에서 노리는 순간:** 1.65초에 위험을 알아보고 3.20초 결과 전에 직접 움직이는 과정. 플레이어가 의자 앞에 없으면 의자가 끼는 장면 자체로도 읽혀야 한다.

터미널에서 먼저 정지·취소했다면 그 상태를 그대로 지킨다. 큰 의자 이동 대신 남은 마지막 묶음이 의자 앞에서 스스로 접혀 쌓이는 짧은 변형을 사용한다. 도중 터미널을 다시 열면 위험한 소품 이동과 사건 시간을 함께 멈춘다. 읽는 동안 의자가 플레이어를 덮치게 하지 않는다.

### P-04 / 수습할 수 있는 행동

화면 목표 교체:

```text
신청서를 회수하고 출력을 멈추세요.
```

플레이어가 선택할 수 있는 수습:

| 행동 | 즉시 결과 | 다음에 남는 상태 |
| --- | --- | --- |
| 바닥 페달 F | 출력 일시정지, 페달 잠금등 점등 | 종이 구조물 높이 고정 |
| 터미널 `pause R41` | 같은 일시정지 | 같은 상태 |
| 터미널 `cancel R41` | 작업 종료 | 현재 종이 구조물과 신청서는 유지 |
| 의자 브레이크 F | 의자만 정지 | 종이는 옆으로 접혀 쌓임 |
| 옆으로 회피 | 충돌 없음 | 의자가 예정된 문틀까지 이동 |
| 종이 위로 올라감 | 종이 구조물을 발판으로 사용 | 약한 밀림만 받음 |

모든 선택을 인정한다. `queue`를 읽어야 페달이 작동하는 조건은 없다. 의자를 먼저 멈추면 문틀 충돌 대사는 생략하며, 소리가 줄어든 자리에 종이 한 묶음이 의자 위로 올라가는 변형을 보여 준다.

`queue` (출력 중):

```text
JOB  FILE           STATE     SENT  ACK
R41  clockout.form  RUNNING   008   0
```

`status`:

```text
PR-01 RUNNING
DELIVERY RETRY
TRAY ACK 0
```

`pause R41`:

```text
R41 PAUSED
```

`cancel R41`:

```text
R41 CANCELLED
QUEUE EMPTY
```

처리 횟수는 실제 상태와 일치시킨다. 시스템 출력에 플레이어를 가르치는 설명이나 예상 사고를 덧붙이지 않는다.

### P-05 / 마지막 묶음 — P02

첫 정지 성공 시 롤러가 멎고 0.55초 정적을 둔다. 이후 이미 롤러 안에 있던 종이 한 묶음이 ‘퍽’ 하고 추가로 나온다. 이 묶음은 장식용이며 고정된 길과 속도로 낙하한다.

앞에 있는 플레이어는 0.5m 밀릴 수 있으나 넘어지거나 진행을 잃지 않는다. 멀리 있으면 바닥에 놓인 컵 하나만 쓰러뜨린다. 이 장면은 작업 정지 성공을 취소하지 않는다.

서유진 `P_SEO_TRAILING`, 추가 묶음 도착 0.7초 뒤:

> 한 장은 한 장인데, 배송을 여러 번 하네요.

반복 재시도에서는 이 대사를 재생하지 않는다. 대사 없이도 마지막 묶음으로 반전이 성립해야 한다.

## 6. 회수 — P-C 내가 만든 종이를 길로 사용

### P-06 / 종이의 규칙

출력이 돌아가면 받침 3개의 종이 두께가 순서대로 올라간다. 각 높이는 0.35m, 0.70m, 1.05m에서 멈춘다. 전부 차는 데 4.5초가 걸리고 이후 종이는 장식 배출구로만 나간다. 높이가 끝없이 올라가 천장에 끼는 일은 없다.

프린터가 정지하면 충돌 모양과 이동도 멈춘다. 다시 돌려도 플레이어 발밑에서 충돌 블록이 순간 솟지 않는다. 각 블록은 최소 0.6초에 걸쳐 이동한다.

회수할 서류는 상부 트레이에서 종이 모서리가 펄럭이며, 가까이에서 제목 ‘퇴근 신청서’가 보인다. 특별한 정답 테두리와 방향 화살표를 띄우지 않는다.

### P-07 / 기본 경로

1. 페달 또는 터미널로 출력 정지.
2. 가까운 낮은 받침에 올라감.
3. 종이 더미 2~3단을 이용해 회수구 접근.
4. F로 신청서 한 장 회수.
5. 낮은 바닥 또는 옆 경사로로 내려옴.
6. 북쪽 받침대에 서류를 놓고 다음 결재석으로 이동.

세 번째 받침에는 넓은 평탄부가 있어 시점을 돌려 목표를 확인할 수 있다. 연속 점프를 실패하면 출력실 바닥으로 내려올 뿐 진행이 초기화되지 않는다.

### P-08 / 인정할 대안

- 출력을 아주 빨리 멈춘 경우: 옆 발판차를 F로 펼친다. 두 단의 고정 계단이 내려와 회수구 옆에 닿는다.
- 출력이 켜진 채 올라간 경우: 종이의 밀림을 버티면서 회수할 수 있다. 서류를 얻은 뒤 정지시키면 완료한다.
- 점프해서 회수구에 먼저 닿은 경우: 범위와 시야가 실제로 맞으면 그대로 회수한다.
- 페달을 발견하지 못한 경우: 터미널에서 작업을 취소한 뒤 같은 공간으로 진행한다.
- 의자에 올라타 배출 경사 끝까지 간 경우: 안전한 낮은 받침에 내려설 수 있다. 접근 순서를 확인해 무효화하지 않는다.

### P-09 / 가벼운 실패

| 실패 | 연출 | 복구 |

밀림은 시야를 빼앗거나 넘어짐 애니메이션으로 카메라를 굴리지 않는다. 같은 접촉이 0.8초 안에 다시 피해를 주지 않는다.

## 7. 성공과 다음 스테이지 연결

완료 조건: `document_recovered == true` AND `job_state == CANCELLED/STOPPED`.

`PAUSED` 상태에서 서류를 회수하면 전달받침대의 작업 종료 스위치 F로 최종 종료할 수 있다. 따라서 pause를 고른 사람이 다시 터미널로 돌아갈 필요는 없다. 스위치는 서류를 올리는 같은 받침대에 있고 ‘출력 종료’라는 정상 표기가 있다.

서유진 `P_SEO_DONE`:

> 됐어요. 이제 결재만 받으면 돼요.

멀리서 오세진이 고개만 든다. 카메라 회전 없음. 무거운 음악 전환 없이 결재석의 작은 종이 벨이 한 번 울린다.

서류를 받침대에 놓으면 저장을 먼저 시도한다. 성공 시 `P-C` 체크포인트 확정, 다음 스테이지 입구를 활성화한다. 저장이 실패하면 서류와 현재 공간을 유지하고 다음 구간으로 넘기지 않는다.

완료 화면이 필요하면 두 행동만 둔다: `다음 업무`, `다시 해 보기`. 큰 실패 횟수 성적표와 긴 성공 설명은 넣지 않는다.

## 8. 상태·이벤트 계약

| 이벤트 ID | 진입 조건 | 바꾸는 상태 | 중복 처리 |
| --- | --- | --- | --- |
| `P_SUBMIT` | 아직 작업이 없고 출력 파일 유효 | job RUNNING, 종이 시퀀스 시작 | 같은 작업 중 추가 제출은 JOB BUSY |
| `P_PAUSE` | RUNNING | PAUSED, 종이 높이 고정 | 이미 정지면 현 상태 출력 |
| `P_RESUME` | PAUSED | RUNNING | CANCELLED 뒤 재개 불가 |
| `P_CANCEL` | RUNNING/PAUSED | CANCELLED | 취소 반복은 성공 상태 유지 |
| `P_BRAKE` | 의자 이동 가능 | chair BRAKED | F 재입력으로 해제 가능, 멈춤턱 안에서는 해제 안 함 |
| `P_CART_OPEN` | 발판차 접힘 | cart OPEN | 펼친 뒤 다시 접지 않음 |
| `P_TAKE` | 회수구 종이 존재, 범위·시야 유효 | document HELD | 인스턴스 중복 생성 금지 |
| `P_PUT` | 전달받침대 접근, HELD | document DELIVERED | 이후 손 슬롯 비움 |
| `P_FINISH` | DELIVERED, 작업 종료 | 저장 후 스테이지 CLEAR | 저장 실패 시 현재 상태 유지 |

초기 상태, 종이 높이, 작업 ID, 회수 문서 ID는 재실행해도 같은 규칙을 쓴다. 연출 진행 프레임을 세이브에 그대로 담지 않는다. 재시작 시 가장 가까운 확정 소구간으로 정규화한다.

## 10. 이 장면이 재미없을 때 고칠 순서

1. P01을 못 봄: PC를 닫았을 때 의자 경로가 시야에 오는 배치부터 수정.
2. 원인을 모름: 출력 성공음 → 롤러 → 종이 → 바퀴의 연결을 더 분명하게 함.
3. 구경만 함: 페달까지 거리를 줄이고 의자의 첫 이동을 0.4초 늦춤.
4. 웃기지만 지루함: 종이 높이가 차는 대기를 줄이고 회수 경로 점프 하나 삭제.
5. 너무 쉬워 기억이 안 남음: 발판을 늘리지 말고 플레이어의 정지 선택에 따른 변형 장면을 강화.
6. 터미널부터 막힘: 도움말의 문법과 파일명 가독성, 입력 포커스를 먼저 확인.

## 11. 첫 구현 인수 조건

- PC를 먼저 쓰거나 NPC에게 먼저 말해도 진행 가능하다.
- 도움말을 보지 않은 숙련자도 정상 명령으로 통과한다.
- 오타·없는 파일·작업 ID 오류로 폭발하지 않는다.
- 정지·취소·의자 브레이크를 누르는 시점마다 다른 수습이 실제 반영된다.
- 출력 1회가 동시 사건 여러 개를 겹쳐 생성하지 않는다.
- 조작 가능한 대표 사건 P01과 정지 뒤 P02가 성공 경로에도 남는다.
- 발판차 우회로와 종이 경로 모두 서류를 회수할 수 있다.
- 서류 유실·소품 끼임으로 처음부터 시작하는 경우가 없다.
- 터미널·메뉴·대화에서는 가변 소품의 위험 진행이 멈춘다.
- 체크포인트 저장 실패 시 다음 단계로 이동하지 않는다.
- 작은 화면에서도 회수 대상과 조작 버튼이 겹치지 않는다.
