# 03 — 저 컴퓨터를 꺼야 해

[전체 설계](DENSE_STAGES.md) · [이전 스테이지](STAGE_02_APPROVAL.md) · [웃음 분석](COMEDY_REFERENCE_ANALYSIS.md).

상태: 구현 전 상세 스크립트. 이 문서에는 플레이어에게 미리 공개하지 않을 사고·폭발·결말 연출이 포함된다.

## 1. 이 스테이지가 하는 일

첫 목표는 마지막 PC의 전원을 끄는 것이다. 전원 덮개를 열자 PC가 의자 바퀴를 펼치고 설비 구역 안쪽으로 도망간다. 플레이어는 앞에서 익힌 출력·브레이크와 새 바람 장치를 조합해 길을 만든 뒤 다시 접근한다.

점프는 만든 경로를 실제로 통과하는 수단이다. 언제 장치를 멈추고 어느 경로를 택할지 결정하는 과정, 짧게 연쇄되는 사고, 도망가는 목표가 함께 있어야 한다.

| 항목 | 목표 |
| --- | --- |
| 화면 제목 | 저 컴퓨터를 꺼야 해 |
| 목표 | 마지막 PC의 전원을 끄세요. |
| 첫 플레이 | 6~8분 |
| 숙련 경로 | 2분 40초~4분 |
| 주요 조작 | 덮개·물리 스위치, 프린터·송풍기, 브레이크, 짧은 점프, 선택 터미널 |
| 핵심 판단 | 종이 경로/의자 경로, 장치를 멈출 위치, 이동 표적의 접근 방향 |
| 대표 장면 | S01: 바퀴 달고 도망가는 PC / S02: 회피한 의자가 다음 의자를 건드림 / S03: 정전 뒤 마지막 한 장 |
| 소구간 | S-A 도주 확인, S-B 중간 작업대, S-C 최종 접근 |
| PC 폭발 | 잘못된 서비스 조작에서 처음 발생 가능. 성공 경로는 폭발 없이도 큰 사건이 있음 |

## 2. 공간의 성격과 마감

기존 임시 옥상 코스가 담당하던 별도 공간을 **사무용 설비가 쌓인 점검 데크**로 다시 설계한다. 사무실 본체·보호 지오메트리는 유지한다. 코드로 허공에 같은 색 상자를 늘어놓는 형태를 최종 배치로 사용하지 않는다.

바닥은 회색 점검 데크, 지지대는 짙은 금속, 임시 종이 구조물은 앞 스테이지와 같은 흰색, 이동 소품은 기존 사무용 의자·작업대 재질을 쓴다. 아래에는 회사 건물의 벽·배관·수거 구역이 보여 공간이 이어진다. 각 높은 표면에는 지지 프레임이 있다.

### 상부 평면 관계

```text
       [종료 후 작은 프린터 / 출구 확인 단말]
                        |
              [최종 작업대 / PC 이동 궤도]
                 ↑                 ↑
             짧은 점프         의자 범퍼 접근
                 └──── [S-C 안전면] ┘
                            ↑
              [의자 C3] → [C4] → [종이 완충벽]
                            ↑
                     [S-B 중간 작업대]
                  ↗                     ↖
       [종이 받침 P1/P2/P3]          [의자 이동 레일]
                  ↑                      ↑
             [PR-02 / 페달]          [F-02 / 풍량 다이얼]
                  └──── [S-A 시작 데크] ────┘
                            |
                    [정비 콘솔 CTL-01]
```

### 필수 치수

- 시작 데크 4.0×3.0m, 중간 작업대 3.2×2.8m, 최종 안전면 3.0×2.5m 이상.
- 최대 연속 필수 점프는 2회. 이후에는 다음 장치를 살피고 숨을 돌릴 안전면이 있다.
- 필수 높이 차 0.30~0.45m, 가장자리 간격 0.65~1.10m. 착지면 폭 최소 1.2m.
- 의자 운반판은 1.5×1.5m 이상의 보강판이 달려 있다. 작은 좌석 쿠션에 정밀 착지하게 하지 않는다.
- 필수 이동 속도는 0.7~1.1m/s, 끝 정지 1.0초. 더 강한 풍량의 빠른 경로는 선택 사항이다.
- 수거 바닥은 출발보다 1.5~2.0m 낮고 보인다. 떨어져도 오랫동안 허공을 내려가지 않는다.
- PC의 마지막 궤도 옆에는 폭 1.2m의 접근 통로와 범퍼를 세울 홈이 있다.
- 최종 전원 스위치는 1.1m 실행 거리와 시야를 모두 요구한다. 멀리서 3.4m 탐색만으로 종료되지 않는다.
- 거리와 시야가 맞으면 바로 성공한다. 특정 발판을 밟았는지 확인하는 숨은 순서 검사는 없다.

## 3. 시작 — S-A 평범한 마지막 업무

### S-00 / 첫 시야

PC-07이 시작 데크 앞의 정상 작업대에 있다. 본체 아래에는 이전 스테이지의 의자 바퀴와 닮은 구조가 조금 보인다. 전원 버튼에는 투명한 플라스틱 덮개가 씌워져 있다.

화면:

```text
STAGE 03 · 저 컴퓨터를 꺼야 해
마지막 PC의 전원을 끄세요.
```

문 너머 오세진 `S_OH_OPEN`:

> 저거 하나만 끄면 됩니다.

입구에서 멈춰 대화를 더 하지 않아도 된다. 최초 접근까지 달리면 3초 안에 도착한다.

### S-01 / 전원 덮개 열기 — S01

표시:

```text
F — 전원 덮개 열기
```

| 입력 후 시각 | 연출 | 플레이어 제어 |
| --- | --- | --- |
| 0.00 | 덮개가 열리기 시작, 잠금 소리 | 자유 이동·시점 |
| 0.25 | 본체 아래 의자 바퀴 네 개가 바깥으로 펴짐 | 플레이어가 이상을 알아볼 시간 |
| 0.55 | 모니터가 플레이어 반대편으로 12도 돌아감 | 카메라 회전 없음 |
| 0.85 | 모터가 한 번 헛돌고 바퀴가 데크를 긁음 | 옆으로 피할 수 있음 |
| 1.20 | PC가 1.1m/s로 정해진 경로를 따라 출발 | 추격·관찰 가능 |
| 2.70 | PC가 중간 경사와 연결 발판을 지나 안쪽으로 이동 | 아직 떨어지는 물체 없음 |
| 4.00 | 최종 작업대에서 정지, 열린 덮개와 버튼이 보임 | 목표를 잃지 않음 |

덮개를 여는 첫 입력은 종료 스위치 입력이 아니다. 실제로 덮개가 버튼을 가리므로 두 행동이 물리적으로 구분된다. 중복 F가 잠긴 스위치를 미리 누르게 하지 않는다. 도착 뒤 실제 버튼이 닿는 경우에는 예정된 도주 횟수를 채우지 않았어도 종료할 수 있다.

PC가 지나간 경로가 잠시 아래로 기울어져 생긴 공간을 보여 준다. 떨어진 발판을 다시 만들어야 한다는 긴 설명은 없다. PR-02와 송풍기 F-02의 모터·종이·바퀴가 눈에 들어온다.

한지우 `S_HAN_RUN`, PC 도착 0.7초 뒤 한 번:

> 저건 또 퇴근이 빠르네.

S-A 체크포인트 확정: PC가 최종 작업대에 도착했고 첫 도주를 본 상태를 저장한다. 이후 실패 재도전에서 S01 전체를 반복하지 않는다. 사용자가 스테이지 전체 다시 하기를 고르면 재생한다.

## 4. 목표를 따라가는 두 경로

### S-02 / 환경 확인

처음 이동할 수 있는 안전 데크에 PR-02, 송풍기 F-02, 정비 콘솔이 함께 있다. 서로 2~3초 이내 거리로 둔다. 필수 파일 세 개를 찾아 사무실 전체를 왕복시키지 않는다.

장치 표지 원문:

```text
PR-02
임시 작업대 출력
```

```text
F-02
0  1  2
```

바닥에는 의자 바퀴의 이동 흔적과 종이가 쌓일 받침이 보인다. 장치 표지는 용도와 현재 상태만 말한다. ‘1로 맞추면 정답’ 같은 문구를 쓰지 않는다.

### S-03 / 종이 경로 — 기본, 안정적

1. PR-02에서 `F — 출력 시작`을 누른다.
2. 출력 종이가 받침 P1/P2/P3에 차례로 쌓이며 각각 0.35m·0.70m·1.05m가 된다.
3. 세 번째 받침까지 형성되면 더 높은 지형을 만들지 않고 종이를 뒤쪽 수거함으로 보낸다.
4. 플레이어는 1스테이지에서 익힌 페달로 어느 시점에든 정지할 수 있다.
5. P1은 시작 데크와 짧은 경사로로 연결된다. P2/P3로 두 번 점프한 뒤 같은 높이의 중간 작업대 S-B로 걸어 이동한다. 낮은 높이에서 정지했다면 한 번 더 출력해 높이를 보충할 수 있다.

출력이 켜져 있을 때 종이 표면이 아주 느리게 밀린다. 정지하면 완전히 고정된다. 플레이어가 멈춰야 한다는 강제 조건은 없으며, 켜진 채 통과하면 그대로 인정한다.

처음 출력 뒤 종이 더미 맨 위에 빈 회의 의자가 한 개 함께 올라온다. 의자는 옆으로 천천히 빠져 수거함에 안전하게 걸린다. 구간을 막는 새 실패 조건이 되지 않는다. 앞에서 알아본 사무용 의자가 또 다른 회사 자산으로 처리되는 작은 연결이다.

### S-04 / 의자 경로 — 이동을 이용하는 대안

1. F-02 다이얼에서 F로 `0 → 1 → 2 → 0`을 순환한다.
2. 풍량 1에서 의자 운반판이 레일을 따라 0.9m/s로 움직이고 양 끝에서 1초 멈춘다.
3. 출발 위치에서 `F — 브레이크 해제`로 운반판을 풀어 준다. 이미 풀려 있으면 해당 표시는 생기지 않는다.
4. 보강판 위에 올라타고 중간 작업대 근처에서 내린다. 앉을 필요는 없고 시점·점프는 그대로 유지한다.
5. 도착 쪽 브레이크를 걸면 운반판을 그 자리에 고정해 이후 재도전의 발판으로 쓸 수 있다.

풍량 2에서는 속도 1.35m/s, 끝 정지 0.7초다. 기계가 고장 나거나 무작위로 폭발하지 않는다. 잘 다루면 더 빠르게 갈 수 있고, 불편하면 다시 1 또는 0으로 바꾼다.

풍량 0에서 운반판을 탔다면 그 자리에 멈춰 있다. 시작 데크에서 다이얼을 바꿔야 하지만 떨어진 사람을 다시 태우려고 모든 설정을 초기화하지 않는다. 정지·재시도 시 운반판은 접근 가능한 가장 가까운 정차점에 정규화한다.

### S-05 / 두 경로를 섞기

- 종이 받침 두 개에서 운반판에 올라타도 통과한다.
- 운반판을 중간에 정지시켜 종이 경로의 큰 틈 하나를 메워도 통과한다.
- 범위·시야가 맞아 PR-02를 멀리서 정지시킨 경우도 인정한다.
- 장치가 가변 상태라 항상 물체의 상대 속도와 판정을 동기화한다. 이동하는 판 위에 서 있어도 플레이어가 아래로 빠지지 않아야 한다.
- 미리 정해 둔 ‘선택 경로’ 플래그로 다른 경로의 발판을 비활성화하지 않는다.

## 5. 선택 터미널 — CTL-01

콘솔은 두 경로를 원격으로 제어하고 상태를 확인하는 대안이다. 터미널을 쓰지 않고 현장 장치만으로도 끝낼 수 있다. 성공 경로를 위해 비밀 명령을 입력해야 하는 구조는 아니다.

최초 화면:

```text
CTL-01
SESSION OPEN
operator@maintenance:~$
```

`help`:

```text
help                  command list
status                device status
ls                    list files
cat <file>            read file
ps                    process list
print <file>          submit print job
pause <job>           pause print job
resume <job>          resume print job
fan <id> <level>      set fan level: 0..2
kill <pid>            stop process
start <pid>           start process
clear  history  exit
```

`status`:

```text
DEVICE  STATE      MODE
PC-07   ON         LOCAL
PR-02   READY      REMOTE
F-02    LEVEL=0    REMOTE
CTL-01  TEMP=61C   FAN=ON
```

`ls`:

```text
platform.job
devices.cfg
maintenance.log
```

`cat devices.cfg`:

```text
PC-07  input=panel  location=deck
PR-02  output=service-tray
F-02   range=0..2
CTL-01 board=operator-console
```

`cat maintenance.log`:

```text
17:58 CTL-01 temp=61 fan=ON
17:59 PC-07 panel=LOCKED link=LOCAL
18:00 PR-02 tray=EMPTY
```

`ps`:

```text
PID  NAME       DEVICE  STATE
12   spoold     PR-02   IDLE
44   coolingd   CTL-01  RUNNING
71   mobilityd  PC-07   RUNNING
```

### 정상 명령의 실제 효과

| 명령 | 결과 출력 | 월드 효과 |
| --- | --- | --- |
| `print platform.job` | `JOB D12 ACCEPTED` | PR-02 현장 출력 버튼과 같은 시작 |
| `pause D12` | `D12 PAUSED` | 종이 높이 고정 |
| `resume D12` | `D12 RUNNING` | 남은 높이까지 형성 |
| `fan F-02 1` | `F-02 LEVEL=1` | 다이얼 1과 동일 |
| `fan F-02 0` | `F-02 LEVEL=0` | 운반판 감속 후 정지 |
| `kill 12` | `PID 12 STOPPED` | 출력 정지, 만들어진 지형 유지 |
| `start 12` | `PID 12 RUNNING` | 출력 서비스 복구, 자동 새 출력은 안 함 |
| `kill 71` | `PID 71 STOPPED` | PC 바퀴 정지. 최종 전원은 여전히 켜져 있음 |
| `start 71` | `PID 71 RUNNING` | 이동 재개. 유효한 선택으로 인정 |

`kill 71`을 발견해 목표를 멈춘 사람에게도 실제 효과를 준다. 그래도 물리 스위치까지의 경로는 지나야 한다. PC-07이 LOCAL인 동안 이 콘솔의 `shutdown`은 지원 명령이 아니며 일반 오류를 반환한다. 지원하지 않는 명령을 입력했다는 이유로 폭발시키지 않는다.

## 6. 첫 폭발 가능 지점 — 잘못된 서비스 조작

### S-06 / `kill 44`

PID 44는 제어 콘솔 자체의 냉각 서비스다. 조회 결과에서 장치 소유자가 드러난다. 명령을 실행하면 멈추는 대상이 실제 콘솔의 작은 팬과 연결되어 있어야 한다.

이 조작을 선택한 경우에만 다음 결과 연출로 진입한다. 평범한 조회·오타·상태 읽기 시간에 폭발 타이머를 진행시키지 않는다.

| 입력 후 시각 | 화면·모델·소리 |
| --- | --- |
| 0.00 | `PID 44 STOPPED`, 콘솔 팬이 멎음 |
| 0.25 | 짧은 팬 정적, 패널 옆 작동등 두 개가 꺼짐 |
| 0.55 | `FAN=0` 한 줄, 전원부에서 작은 빛 |
| 0.85 | 키보드가 한 번 들썩임. 닫힌 프레임에서 본체 일부가 부풀어 보임 |
| 1.15 | 콘솔 모니터와 본체 메시가 실제로 분리되어 튀어나감 |
| 1.45 | 파편이 바닥에 닿음. 화면 흔들림은 짧고 수평 위주 |
| 1.95 | 0.5초 정적 뒤 재도전 행동 표시 |

연출은 사용자가 확정한 장치 조작의 결과다. 명령 결과 표시 후 콘솔이 파손되면서 터미널을 닫고 현재 카메라 방향에서 사건을 본다. 사고 구경을 위해 자동 3인칭으로 바꾸지 않는다. 메뉴를 열면 결과 연출도 일시정지한다.

원문 출력:

```text
PID 44 STOPPED
FAN=0
I/O LOST
```

실패 화면 문구:

```text
콘솔이 먼저 퇴근했습니다.
다시 하기
메뉴
```

오세진에게 실패 전후 농담을 추가로 겹치지 않는다. 첫 폭발은 소리·공간·정적만으로 충분한지 먼저 본다. 실제 설정 UI·도움말·소개에 이 실패를 예고하는 문구를 넣지 않는다.

### 폭발 복구 계약

- 마지막 확정 체크포인트 S-A/S-B/S-C로 돌아간다. 1·2스테이지를 다시 하지 않는다.
- 원본 CTL-01 모델을 복구하고 장식 파편·임시 조명·연출 타이머를 제거한다.
- 콘솔의 입력 이력은 남긴다. 마지막 위험 명령을 자동 재실행하지 않는다.
- 일반 조회 출력은 다시 볼 수 있고, 다른 경로 선택도 가능하다.
- 파손 복구가 끝나기 전에 이동·타깃 감지를 재개하지 않는다.
- 실패 화면에서 Esc를 누르면 일시정지 메뉴로 간다. 파손된 공간에서 조작이 풀리지 않는다.
- 뒤에 새 서비스 오답을 세 개 더 만들어 분량을 늘리지 않는다. 첫 버전의 오조치는 이 한 가지로 충분하다.

## 7. 중간 구간 — S-B 짧은 연쇄 사고

### S-07 / 체크포인트

중간 작업대에 도착해 바닥에 0.2초 이상 서 있으면 S-B 저장을 시도한다. 저장 성공음은 작은 회사 단말 소리 한 번이다. 이후 추락하면 경로 설정과 첫 도주 상태를 보존한 채 이 작업대로 돌아온다.

안전면에서 앞쪽 의자 C3, 그 뒤의 C4, 종이 완충벽이 한눈에 보인다. 첫 의자가 바람에 조금 흔들리며 한쪽 바퀴가 움직이는 모습을 0.8초 보여 준다.

### S-08 / S02의 연쇄

S-B를 벗어나는 좁지 않은 통로 앞에서 다음 연쇄가 시작한다. 같은 체크포인트 재시도에서는 주기가 처음부터 동일하다.

| 시각 | 물체 | 대응 여지 |
| --- | --- | --- |
| 0.00 | C3 바퀴가 천천히 움직임 | 옆 안전면으로 회피 가능 |
| 0.80 | C3이 플레이어 앞 경로를 가로지름 | 점프·정지·브레이크 가능 |
| 1.20 | C3이 C4의 등받이를 건드림 | 첫 물체를 피한 플레이어가 다음 원인을 볼 시간 |
| 1.70 | C4가 낮은 종이 벽을 밀어 종이 한 묶음이 옆으로 넘어옴 | 낮은 받침 위로 이동하거나 뒤로 물러날 수 있음 |
| 2.25 | 마지막 빈 의자 바퀴만 ‘톡’ 하고 돌아감 | 추가 피해 없음 |

연쇄 중 직접 충돌은 최대 세 번, 전체 강제 밀림은 최대 1.8초다. 첫 충돌 후 0.65초 동안 동일 물체의 재접촉을 무시한다. 이탈 방향을 고를 이동 입력은 유지한다. 카메라를 쓰러뜨리지 않는다.

### S-09 / 잘한 대응에 대한 변형

- C3 브레이크를 미리 잡음: C4가 혼자 출발하려다 제자리에서 바퀴만 돌고 멈춘다. 통과 경로는 열린다.
- 첫 의자를 점프로 넘음: C3은 뒤에서 C4와 부딪히고 종이가 위로 작게 솟는다. 플레이어를 자동으로 다시 맞히지 않는다.
- 종이 벽 옆을 우회함: 충돌 없이 작은 종이 폭포를 옆에서 본다.
- 운반판을 이 구간까지 고정해 둠: 위쪽 안전면으로 지나갈 수 있다. 발판을 강제로 회수하지 않는다.
- 의자를 타고 넘어감: 착지가 유효하면 같은 체크포인트를 받는다.

서유진이 멀리서 한 번만 `S_SEO_CHAIN`:

> 의자는 제자리에 놓고 가세요.

대사는 연쇄가 끝난 0.6초 뒤다. 이 말을 듣기 위해 멈추거나 카메라를 돌리게 하지 않는다.

## 8. 최종 접근 — S-C PC의 마지막 움직임

### S-10 / 가까워진 전원 버튼

최종 안전면에 서면 PC의 열린 덮개와 전원 표시등이 보인다. 여기까지의 상태를 S-C로 저장한다. 남은 구간은 숙련 시 10~20초 안에 다시 시도할 수 있어야 한다.

PC 이동 서비스가 켜져 있으면 최종 궤도에서 두 정차점을 오간다.

| 구간 | 시작값 |
| --- | --- |
| 정차점 사이 거리 | 2.4m |
| 이동 속도 | 1.1m/s |
| 끝 정차 | 1.2초 |
| 범퍼 설치 홈 | 경로 옆 고정 홈 1개 |
| 버튼 실행 거리 | 1.1m |

플레이어가 가까워질 때마다 무조건 더 멀리 도망가게 하지 않는다. 정해진 구간을 왕복하므로 배우면 따라잡을 수 있다. 도망 이동이 더 일어나야 한다는 카운트도 없다.

### S-11 / 기본 해결

1. 넓은 안전면에서 왕복 경로를 확인한다.
2. PC가 가까운 정차점으로 올 때 접근한다.
3. 의자 바퀴 브레이크 F로 PC를 정지시킨다.
4. 열린 덮개 안의 스위치를 바라보고 F로 누른다.

브레이크를 먼저 잡지 않고 정차점에서 전원 버튼에 닿아도 성공한다. 달려드는 플레이어와 PC가 맞부딪히면 안전 범퍼가 잠깐 정지해 주므로 무한 추격으로 바뀌지 않는다.

### S-12 / 지름길과 실험

- 앞에서 `kill 71`로 이동 서비스를 멈췄다면 PC는 이미 정지해 있다. 그대로 전원을 끈다.
- 빈 의자를 범퍼 홈에 넣으면 PC가 앞에서 멈춘다. 2스테이지에서 알아본 해결법을 회수한다.
- 풍량을 0으로 줄여 이동 구간을 안전하게 만든 뒤 접근할 수 있다. PC의 독립 모터는 바람 정지로 꺼지지 않는다.
- 여러 발판을 건너뛰어 버튼까지 실제로 닿으면 성공으로 처리한다.
- 파손된 콘솔의 장식 파편은 발판으로 판정하지 않는다. 재도전 난수로 우연히 이득·손해가 생기지 않게 한다.
- 높은 점프·짧은 공중 접근으로 누른 경우에도 거리·시야·전원 상태가 유효하면 성공이다. 착지 순서를 강제하지 않는다.

## 9. 종료 사건 — S03 마지막 한 장

### S-13 / 눌렀다

최종 전원 입력이 유효하면 `PC-07 OFF`를 먼저 확정한다. 그 뒤 회사의 정전 연출이 이어진다. 성공한 플레이어를 마지막에 떨어뜨리거나 승인 상태를 취소하지 않는다.

| 스위치 후 시각 | 연출 |
| --- | --- |
| 0.00 | 작은 스위치 클릭, PC 화면 꺼짐, 바퀴 정지 |
| 0.30 | 점검 데크 조명 하나 꺼짐 |
| 0.55 | 뒤쪽 사무실 조명도 순서대로 꺼짐 |
| 0.90 | 모터·팬·키보드 소리 모두 멎음 |
| 1.50 | 어둠 속에서 작은 비상등만 남음 |
| 2.10 | 입구 쪽 프린터 롤러 소리 한 번 |
| 2.80 | 종이 한 장이 아래로 미끄러져 내려옴 |
| 3.50 | 종이의 제목이 비상등 아래서 보임 |
| 4.10 | 팀장의 짧은 반응 |
| 5.10 | 출구 확인 단말의 작은 성공음 |

종이 원문:

```text
퇴근 확인서
처리: 완료
출력: 1장
```

오세진 `S_OH_BLACKOUT`:

> 원본은 챙기세요.

종이는 손 슬롯이 비어 있으면 F로 집을 수 있다. 집지 않아도 퇴근 완료다. 엔딩을 확인하기 위해 새로운 서류 제출 단계를 추가하지 않는다.

플레이어는 비상등이 비추는 출구로 2~3초 걸어갈 수 있다. 최종 완료 저장이 성공하면 종료 화면이 열린다. 문 앞에서 다음 업무를 억지로 다시 주는 반전은 없다.

마지막 화면:

```text
퇴근했습니다.
다시 출근하기
메인 화면
게임 종료
```

정전은 게임 안 조명과 소리에만 적용한다. 창·화면 밝기 설정, 실제 OS 전원, 사용자의 장치에는 연결하지 않는다. 제작 문서의 이 설명을 게임 대사·터미널 출력으로 삽입하지 않는다.

## 10. 실패와 체크포인트

| 실패 | 보여 줄 것 | 돌아갈 곳 | 보존 |
| --- | --- | --- | --- |
| 종이 경로에서 추락 | 떨어지는 방향과 수거 바닥, 최대 1.5초 | S-A 또는 S-B | 첫 도주, 출력·풍량 설정 |
| 의자 운반판에서 추락 | 운반판이 계속 가다가 정차점에서 멈춤 | 마지막 안전 데크 | 운반판을 접근 가능한 정차점에 배치 |
| 연쇄에 밀려 추락 | 첫 원인과 두 번째 충돌까지 보임 | S-B | 길 생성 완료 |
| 마지막 버튼 앞에서 추락 | PC가 멀리 달아나지 않고 같은 궤도에 남음 | S-C | 이동 서비스·브레이크 상태 |
| CTL-01 폭발 | 본체·모니터 파손과 파편 | 마지막 확정 체크포인트 | 앞선 모든 스테이지·첫 도주 |
| 완료 저장 실패 | 꺼진 PC와 비상등 유지 | 현장 | 성공 상태를 메모리에 유지, 저장 재시도 가능 |

도중 재실행 시 공중 위치를 복원하지 않는다. 마지막 체크포인트의 평탄부, 유효한 경로 설정, 정차한 가변 소품으로 시작한다. 플레이어 위나 발밑에서 경로가 생성되지 않는다.

표의 경로 설정 보존은 우선 현재 실행 중 재시도의 계약이다. 장치를 조작해 안정 상태가 됐을 때 설정을 저장할 수 있으나, 재실행에는 마지막으로 저장에 성공한 설정만 복원한다. 아직 저장하지 못한 연출 프레임이나 공중 이동을 복원했다고 표시하지 않는다.

## 11. 상태·이벤트 계약

| 이벤트 ID | 진입 | 결과 |
| --- | --- | --- |
| `S_COVER` | 덮개 닫힘, 플레이어 접근 | 덮개 열기, 도주 이벤트 한 번 시작 |
| `S_RUN_END` | PC 도착 | S-A 저장, 최종 궤도 대기 |
| `S_PRINT_START/PAUSE` | PR-02 조작 또는 정상 명령 | 같은 종이 경로 상태 변경 |
| `S_FAN_SET` | 0..2 유효 입력 | F-02 풍량과 운반판 속도 변경 |
| `S_MOBILITY_STOP` | 정상 `kill 71` | PC 궤도 이동 정지 |
| `S_COOLING_STOP` | 정상 `kill 44` | CTL-01 파손 결과 상태 진입 |
| `S_REACH_MID` | 중간 평탄부 안정 착지 | S-B 저장 |
| `S_CHAIN` | S-B 이후 통로 진입 | 정해진 짧은 의자 연쇄 한 번 |
| `S_REACH_FINAL` | 최종 안전면 착지 | S-C 저장 |
| `S_PC_BRAKE` | PC 바퀴에 유효 접근 | 현재 궤도 위치에서 정지 |
| `S_POWER` | PC ON, 실제 버튼 거리·시야 유효 | PC OFF, 성공·정전 연출 |
| `S_COMPLETE` | PC OFF, 완료 저장 성공 | 전체 COMPLETE |

조회와 소품 조작은 진행 상태를 항상 같은 규칙으로 바꾼다. 스크립트 타임라인이 다른 해결 경로의 성공을 뒤늦게 취소하지 않는다. 재도전 시 남아 있는 이벤트·신호 연결로 PC가 두 번 도망가거나 두 번 폭발하지 않게 한다.

## 13. 재미가 약할 때 고칠 순서

1. S01이 안 읽히면 도망 속도를 늦추고 바퀴 전개를 더 선명하게 한다.
2. 길 만들기가 정답 버튼 누르기처럼 느껴지면 두 경로를 섞을 수 있는 연결과 장치 정지 위치를 늘린다.
3. 이동이 늘어지면 발판을 빼고 원인 있는 장치 하나를 가까이 둔다.
4. S02가 억울하면 첫 움직임 예고와 회복 공간부터 늘린다. 체크포인트를 뒤로 보내지 않는다.
5. PC를 계속 따라가기만 하면 끝 정지 시간을 늘리고 범퍼 접근을 넓힌다.
6. 엔딩이 말로만 웃기면 대사를 빼고 정전 → 정적 → 종이 1장의 소리 간격부터 조정한다.
7. 폭발을 보지 못해도 재미있는지 성공 경로를 반드시 별도로 평가한다.

## 14. 첫 구현 인수 조건

- 1인칭을 유지하고 주요 사건 때문에 카메라를 강제로 돌리지 않는다.
- 최초 전원 덮개와 실제 전원 버튼이 시각·충돌에서 구분된다.
- 출력·의자 경로, 혼합 경로가 실제로 통과 가능하다.
- 조회·오타는 일반 오류이며 문서에 없는 임의 폭발 조건이 없다.
- `kill 71`이 실제로 PC 이동을 멈추고 부당한 대체 도주가 발생하지 않는다.
- `kill 44`는 실제 콘솔 모델을 파손하고 재시도 때 완전히 복구한다.
- 넉백 횟수·시간 상한을 지키고 입력 버퍼·코요테 타임이 동작한다.
- S-B 이후 추락으로 첫 도주·길 만들기를 반복시키지 않는다.
- PC 버튼의 유효한 조기 접근과 지름길을 성공으로 인정한다.
- 정전 후 성공을 취소하거나 새 필수 업무를 주지 않는다.
- 완료 저장 실패 시 원래 저장과 현재 성공 상태를 보존한다.
